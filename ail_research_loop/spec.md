# AIL + MoIE Recursive Research Protocol
## Formal Specification v1.0

**Status:** Reference specification
**Scope:** Hypothesis-driven research generation, execution, evidence synthesis, JEV routing, theory update, and recursive re-entry.
**Design principle:** The system proposes; experiments produce evidence; evidence updates the research state.

---

## 1. Purpose

This specification defines a machine-readable and executable protocol for transforming a problem into a falsifiable research cycle and recursively feeding the resulting evidence back into the research process.

The complete protocol is:

`PROBLEM -> ASSUMPTIONS -> INVERSION -> MECHANISMS -> HYPOTHESIS -> PREDICTIONS -> EXPERIMENT -> EXECUTION -> EVIDENCE -> SYNTHESIS -> JEV -> THEORY UPDATE -> NEXT HYPOTHESIS`

The protocol explicitly supports:

- positive results;
- null results;
- contradictory evidence;
- conditional results;
- confounded results;
- novel findings;
- failed experiments;
- and recursive theory revision.

No component is permitted to convert model confidence into scientific truth.

---

## 2. Design Goals

### 2.1 Required properties

1. **Falsifiability:** every active hypothesis has at least one explicit failure condition.
2. **Traceability:** every claim points to evidence.
3. **Separation of concerns:** proposal, execution, evidence, and theory update are different states.
4. **Non-retroactivity:** preregistered predictions cannot be silently changed after results exist.
5. **Fail-closed routing:** insufficient or conflicting evidence must not be promoted as established knowledge.
6. **Recursive re-entry:** completed cycles generate structured material for the next cycle.
7. **Reproducibility:** execution artifacts and provenance are first-class objects.
8. **Human authority:** human intent/constraints remain outside the model's authority to redefine.

### 2.2 Non-goals

This specification does not claim that AIL, MoIE, or JEV guarantees scientific correctness, discovery, general intelligence, or domain expertise.

## 5. Research State Machine

### 5.1 States

```text
DRAFT
  -> PROBLEM_DEFINED
  -> HYPOTHESIS_FORMED
  -> PREREGISTERED
  -> READY_TO_EXECUTE
  -> EXECUTING
  -> RESULTS_AVAILABLE
  -> EVIDENCE_SYNTHESIZED
  -> JEV_EVALUATED
  -> THEORY_UPDATED
  -> REENTRY_READY
  -> COMPLETE
```

Exceptional states:

```text
BLOCKED
FAILED_EXECUTION
INVALIDATED
```

### 5.2 State semantics

| State | Meaning | Required condition |
|---|---|---|
| `DRAFT` | Incomplete cycle | Minimum envelope exists |
| `PROBLEM_DEFINED` | Research question is operationalized | Problem + domain + objective exist |
| `HYPOTHESIS_FORMED` | Competing mechanisms and candidate hypothesis exist | H0/H1/alternative present |
| `PREREGISTERED` | Predictions and falsification rules frozen | Predictions immutable thereafter |
| `READY_TO_EXECUTE` | Experiment is executable | Code/data requirements satisfied |
| `EXECUTING` | Experiment currently running | Execution started |
| `RESULTS_AVAILABLE` | Raw results exist | Execution complete |
| `EVIDENCE_SYNTHESIZED` | Raw results normalized into evidence | Evidence summary + breakdown exist |
| `JEV_EVALUATED` | Evidence has been routed/classified | JEV decision exists |
| `THEORY_UPDATED` | Research model updated from evidence | Theory update exists |
| `REENTRY_READY` | Next cycle can begin | Next hypothesis/test generated or explicit stop |
| `COMPLETE` | Cycle archived | Immutable archive created |
| `BLOCKED` | Human or governance boundary prevents progression | Blocking reason recorded |
| `FAILED_EXECUTION` | Planned execution could not complete | Error and recovery status recorded |
| `INVALIDATED` | Cycle structurally invalid | Validation error recorded |

### 5.3 Allowed transitions

```text
DRAFT -> PROBLEM_DEFINED
PROBLEM_DEFINED -> HYPOTHESIS_FORMED
HYPOTHESIS_FORMED -> PREREGISTERED
PREREGISTERED -> READY_TO_EXECUTE
READY_TO_EXECUTE -> EXECUTING
EXECUTING -> RESULTS_AVAILABLE
EXECUTING -> FAILED_EXECUTION
RESULTS_AVAILABLE -> EVIDENCE_SYNTHESIZED
EVIDENCE_SYNTHESIZED -> JEV_EVALUATED
JEV_EVALUATED -> THEORY_UPDATED
THEORY_UPDATED -> REENTRY_READY
REENTRY_READY -> COMPLETE
REENTRY_READY -> PROBLEM_DEFINED

Any non-terminal state -> BLOCKED
BLOCKED -> previous_state (only after blocking condition resolved)
DRAFT|... -> INVALIDATED when schema/integrity validation fails
FAILED_EXECUTION -> READY_TO_EXECUTE after explicit recovery revision
```

### 5.4 Transition guards

A transition is valid only when all required objects and invariants are satisfied.

Examples:

- `HYPOTHESIS_FORMED -> PREREGISTERED` requires a frozen H0, H1, alternative, and falsification criterion.
- `PREREGISTERED -> READY_TO_EXECUTE` requires a runnable experiment specification and declared data source.
- `RESULTS_AVAILABLE -> EVIDENCE_SYNTHESIZED` requires raw outputs and execution metadata.
- `EVIDENCE_SYNTHESIZED -> JEV_EVALUATED` requires at least one evidence item or an explicit `NO_EVIDENCE` decision.
- `JEV_EVALUATED -> THEORY_UPDATED` requires a JEV classification and rationale.
- `THEORY_UPDATED -> REENTRY_READY` requires either an updated hypothesis or a justified stop condition.

## 7. AIL Procedure

AIL is a hypothesis-generation operator.

### 7.1 Input

- problem
- domain assumptions
- observations

### 7.2 Procedure

1. Identify at least one load-bearing assumption.
2. State why the assumption matters.
3. Construct a meaningful inversion.
4. Derive the alternative mechanism.
5. State the observable consequence.
6. Identify at least one condition where the inversion should fail.

### 7.3 Rule

`INVERSION != PROOF`

An inversion can only create a candidate explanation.

---

## 8. MoIE Procedure

MoIE is a structured mixture of epistemic roles.

Minimum roles:

- **Inversion Critic:** finds load-bearing assumptions.
- **Deviant Scout:** searches anomalies, boundary conditions, counterexamples.
- **Synthesizer:** creates competing mechanisms.
- **Red Team:** attempts falsification.
- **Predictor:** converts mechanisms into preregistered measurable predictions.

A MoIE result is valid only if disagreement is preserved when evidence does not discriminate.

`MAJORITY != TRUTH`

## 9. JEV Decision Procedure

JEV is a routing/classification procedure over evidence-to-claim relationships.

### 9.1 Inputs

- target prediction or theory claim
- evidence items
- thresholds
- contradiction policy

### 9.2 Evidence quality weight

For evidence item `e`:

```text
quality(e) =
    0.25 * directness
  + 0.20 * reproducibility
  + 0.15 * independence
  + 0.20 * method_quality
  + 0.10 * confound_control
  + 0.10 * consistency
```

Then apply source reliability multiplier:

| Source type | Multiplier |
|---|---:|
| executed_code | 1.00 |
| real_dataset | 1.00 |
| human_observation | 0.90 |
| synthetic_data | 0.80 |
| literature | 0.75 |
| model_assertion | 0.20 |

The multiplier does not mean synthetic experiments are “bad.” It means they have narrower external-validity weight than directly observed real systems.

### 9.3 Support and contradiction

For each evidence item:

```text
weighted_support(e) = quality(e) * source_multiplier(e)
weighted_contradiction(e) = weighted_support(e) if contradictory else 0
```

Evidence supporting the target receives support weight.
Evidence contradicting the target receives contradiction weight.

Normalize each total by the sum of all relevant evidence weights.

### 9.4 Quality gate

Define:

```text
quality_score = weighted_mean(quality(e))
```

The default minimum quality gate is `0.60`.

### 9.5 Decision thresholds

Default thresholds:

```text
PROMOTE_THRESHOLD = 0.70
CONTRADICTION_THRESHOLD = 0.70
MARGIN_THRESHOLD = 0.15
```

Classification procedure:

1. If no relevant evidence exists -> `UNKNOWN`.
2. If a materially new observation is outside current theory/predictions and is not adequately represented -> `NOVEL`.
3. If both support and contradiction exceed `0.30` and neither dominates by at least `MARGIN_THRESHOLD` -> `CONFOUND`.
4. If support exceeds `PROMOTE_THRESHOLD`, contradiction is below `CONTRADICTION_THRESHOLD`, and quality gate passes -> `EQUAL`.
5. If contradiction exceeds `CONTRADICTION_THRESHOLD`, support is below `0.30`, and quality gate passes -> `NOT_EQUAL`.
6. If support is nonzero but below promotion threshold, with contradiction low -> `PARTIAL`.
7. If the evidence supports the claim only under explicitly bounded conditions -> `CONDITIONAL`.
8. Otherwise -> `UNKNOWN`.

### 9.6 Conditional override

`CONDITIONAL` is preferred over `EQUAL` whenever all observed support is bounded by a declared regime, parameter range, population, or experimental setup.

Example:

> “Supported for beta >= 0.20 under static N=1000 SIR simulations.”

This prevents a bounded experiment from being promoted as a universal claim.

### 9.7 Confound priority

JEV MUST prefer `CONFOUND` over `EQUAL`, `PARTIAL`, or `CONDITIONAL` when:

- the dominant support depends on an uncontrolled variable;
- two causal mechanisms remain empirically indistinguishable;
- or an adversarial control produces the same outcome through an alternate mechanism.

### 9.8 Human escalation

JEV SHOULD escalate to a human when:

- contradiction and support are both high;
- the decision changes an externally consequential action;
- evidence quality is below the promotion threshold but stakes are high;
- or the requested action exceeds the declared authority boundary.

## 10. Evidence-Weighting Rules

### Rule E1 — Direct execution outranks assertion

Executed experimental output is weighted above model prose.

### Rule E2 — Independent replication increases weight

Independent runs should not be double-counted as fully independent when they share identical failure modes or identical generated data.

A conservative implementation should cap correlated evidence clusters.

### Rule E3 — Reproducibility matters

Evidence that another executor can reproduce receives higher weight than a one-off run.

### Rule E4 — Confounds reduce weight

Evidence with known uncontrolled confounds cannot be treated as high-quality causal evidence.

### Rule E5 — Negative results are first-class evidence

A failed hypothesis remains part of the record and can reduce support for a theory.

### Rule E6 — Synthetic evidence has bounded scope

Synthetic experiments can establish internal behavior of the specified model but do not automatically establish real-world external validity.

### Rule E7 — Model-generated claims are weak evidence until executed

A model's explanation is not independently supporting evidence if it derives from the same model that generated the hypothesis.

### Rule E8 — Contradiction cannot be erased by averaging

Conflicting evidence must remain explicit.

### Rule E9 — Scope follows experiment

The scope of the conclusion cannot exceed the scope of the population, data, parameter regime, and execution method actually tested.

### Rule E10 — New evidence triggers re-entry

A sufficiently material observation produces a `TheoryUpdate` object and, unless a justified stop condition exists, a next hypothesis or discriminating test.

## 11. Recursive Re-Entry Procedure

After JEV evaluation:

1. Produce one-paragraph evidence summary.
2. Produce complete research overview.
3. Produce detailed evidence breakdown.
4. Route evidence through JEV.
5. Identify what changed relative to the prior theory.
6. Create a theory update.
7. Identify remaining uncertainty and competing explanations.
8. Create the next hypothesis or explicit stop condition.
9. Freeze the completed cycle as an immutable archive.
10. Begin a new `ResearchCycle` with the updated theory as input.

Formally:

```text
R_(n+1) = Update(R_n, E_n, JEV_n)
```

The recursive update is not permitted to overwrite the original cycle.

---

## 12. Immutability and Audit

Once `PREREGISTERED` is reached:

- predictions are immutable;
- falsification thresholds are immutable;
- experiment definition is immutable unless a new versioned cycle is created.

Once `COMPLETE` is reached:

- raw results are immutable;
- evidence references are immutable;
- JEV decision is immutable.

Corrections MUST be represented as new versions, not silent edits.

## 13. Minimal Reference Workflow

```text
problem = intake()
assumptions = identify_assumptions(problem)
inversions = ail_invert(assumptions)
mechanisms = moie_generate(inversions)
hypothesis = synthesize_hypothesis(mechanisms)
predictions = preregister(hypothesis)
experiment = compile_experiment(problem, hypothesis, predictions)
results = execute(experiment)
evidence = synthesize_evidence(results)
jev = decide(evidence, hypothesis)
theory = update_theory(hypothesis, evidence, jev)
next_cycle = reenter(theory)
```

---

## 14. Minimal Correctness Properties

A reference implementation SHOULD satisfy at least:

- illegal state transitions are rejected;
- post-preregistration prediction mutation is rejected;
- missing evidence produces `UNKNOWN`;
- high contradiction prevents unsupported promotion;
- bounded support may produce `CONDITIONAL` rather than `EQUAL`;
- theory updates retain prior theory;
- negative results remain archived;
- every final decision can be traced to evidence IDs.

---

## 15. Interpretation

This protocol operationalizes a simple research principle:

> **An idea becomes scientifically actionable when it can generate a falsifiable hypothesis, a discriminating test, and an evidence trail that can change the next hypothesis.**

The core loop is therefore not “generate answers.”

It is:

> **generate -> test -> learn -> re-enter.**
